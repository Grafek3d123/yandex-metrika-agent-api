Task05 считаем закрытым.

Новый функционал пока НЕ добавлять. MCP пока НЕ добавлять. Новые AI tools пока НЕ добавлять.

Сделай финальный end-to-end audit текущего проекта с позиции главной задачи проекта:

«KodaCode AI Agent должен через Yandex Metrica integration уметь безопасно работать со счётчиками, целями и статистикой пользователя».

Проверь именно существующую реализацию.

### 1. AI Agent → AI Tools

Проверь, что реальные сценарии пользователя корректно проходят через ToolRegistry:

* определить/выбрать counter;
* получить traffic;
* получить traffic by day;
* получить sources;
* получить top pages;
* получить goal stats;
* сравнить периоды;
* получить список goals;
* получить конкретную goal;
* создать goal;
* изменить goal;
* удалить goal через confirmation flow.

### 2. Safety

Отдельно проверить:

* read-only tools выполняются без confirmation;
* обычные create/update операции работают штатно;
* delete_goal без confirmation НЕ вызывает DELETE;
* `confirmed=true` от AI не является обходом;
* fake/expired/reused/wrong-resource confirmation не проходит;
* настоящий пользовательский confirmation позволяет выполнить ровно одну операцию;
* после Task05 не осталось другого destructive пути, через который AI может удалить ресурс напрямую.

### 3. Реальный API

Если возможно, выполнить существующий acceptance flow против реального Yandex Metrica API.

Не создавать новые постоянные данные. Для тестов использовать временные ресурсы и обязательно cleanup.

### 4. Проверить API contract

Убедиться, что текущие tools действительно соответствуют официальному API:

* counters;
* goals CRUD;
* Reports API;
* goal metrics;
* OAuth;
* ошибки 401/403/404/429/420;
* rate limiting.

### 5. Проверить agent usability

Для каждого основного tool ответ должен быть понятен AI Agent:

* успешный результат;
* needs_input;
* confirmation_required;
* ошибка API.

Не должно требоваться знание AI Agent'ом внутренних `metrics`, `dimensions`, `filters`, URL endpoints или OAuth деталей.

### 6. Проверить публичный API проекта

Проверить imports/exports и документацию:

* что реально является public API;
* что можно импортировать из package;
* README соответствует текущему коду;
* нет устаревших примеров;
* нет заявлений о возможностях, которых фактически нет.

### 7. Quality gates

Запустить:

* pytest;
* ruff;
* mypy strict;
* compileall.

### 8. Главное правило

Это AUDIT ONLY.

Не вносить изменения в код без отдельного согласования.

В отчёте разделить:

A. PASS — действительно работает;

B. FAIL — реально блокирует готовность;

C. LIMITATION — ограничение, но не блокер;

D. NICE TO HAVE — можно сделать позже.

В конце дать один чёткий итог:

READY / NOT READY.

Если NOT READY — указать максимум 3 главных блокера и почему они блокируют готовность.

Не предлагать новые функции просто ради расширения проекта.
